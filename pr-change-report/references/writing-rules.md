# 무엇을 넣고 어떻게 쓰는지

## 무엇을 넣을지
정해진 목차가 없습니다. 이 PR 을 이해하는 데 필요한 것만 고릅니다. 작은 PR 은 절 하나로 끝냅니다.

| 변경에 이런 것이 있으면 | 이렇게 보여 줍니다 |
|---|---|
| 배치·요청의 한 단계를 바꿈 | `flow` 로 그 배치·요청 전체가 하는 일을 그리고, 바꾼 단계를 `changed` 로 표시 |
| 처리 순서·호출 구조가 바뀜 | `sequence` 이전·이후 두 개 |
| 로직이 바뀜 | `compare` (python) 로 바뀐 부분만 |
| ORM 쿼리가 바뀜 | `compare` (sql). ORM 코드가 아니라 그 코드가 만드는 SQL 을 이전·이후로 |
| 모델·테이블을 읽고 쓰는 방식이 바뀜 | `tables` 로 관련 테이블 ERD. 모델 정의를 읽고 표 사이의 관계 선까지 그립니다 |
| 응답·알림·저장되는 값이 달라짐 | `table` 로 항목별 이전·이후 |
| 동작은 같고 구조만 바뀜 | 같다고 볼 근거(테스트 이름과 확인하는 것)를 `table` 로 |
| PR 본문·테스트에 측정값이 있음 | `kpis`, `bars` |

- 읽는 사람이 diff 만 보고 바로 알 수 있는 것은 넣지 않습니다. 파일 목록, 이름 변경, import 정리가 그렇습니다.
- `flow` 는 처음 보는 사람이 기능을 파악하는 그림입니다. 함수 안의 세부 절차(잠금, 읽기, 저장)가 아니라 업무 단계(복사, 확인, 지급, 알림)를 씁니다. 세부 절차는 `sequence` 나 `compare` 로 보여 줍니다. 언제 무엇이 시작시키는지는 `caption` 에 씁니다.
- 복잡한 흐름(호출 순서, 반복, 재시도)은 글로 풀어 쓰지 않고 `sequence` 나 `flow` 로 그립니다. "그다음", "그 뒤", "이때"로 단계를 이어 가는 문단은 그림으로 바꿉니다.
- 바뀐 것은 한 줄에 하나씩 명사로 적습니다. 예: "잔액 SUM 3번 → 1번", "알림 발송을 celery 태스크로 이동". 문장은 `lead` 와 그림을 읽는 데 필요한 한두 줄에만 씁니다.
- 같은 내용을 글과 표에 두 번 쓰지 않습니다. 표·비교·그림이 본문이고 글은 그것을 읽는 데 필요한 한두 문장입니다.
- 이전·이후는 떨어뜨리지 않고 한 블록에서 나란히 보여 줍니다.
- 숫자는 PR 본문·테스트·코드에 실제로 적힌 값만 씁니다. 예상 효과를 지어내지 않습니다. 값이 없으면 `kpis`·`bars` 를 뺍니다.
- 확인하지 못한 것은 쓰지 않습니다. 코드에서 호출 경로를 찾지 못한 설명은 뺍니다.
- PR 본문과 코드가 다르면 코드를 따릅니다. PR 본문에만 있는 내용은 `caption` 이나 칸에 "PR 본문 기준"이라고 적습니다.
- 테스트를 근거로 쓸 때는 그 테스트 본문을 읽고 실제로 확인하는 것을 적습니다.
- 장애 건수처럼 변경 전후를 비교한 값이 아닌 숫자는 `kpis`·`bars` 에 넣지 않습니다.

## SQL 비교
- 테이블 이름은 모델의 `db_table`(없으면 `앱라벨_모델명`)을 씁니다. SELECT 목록은 `...` 로 줄이고, 바뀐 절만 남깁니다.
- 바뀐 줄 앞에 `!` 를 붙이면 이전은 `-`, 이후는 `+` 로 표시됩니다.
- 반복 실행은 SQL 주석으로 적습니다. 예: `-- 리뷰마다 1번`.
- 실행해서 얻은 SQL 이 PR 본문이나 테스트에 있으면 그것을 쓰고 `sql_source` 를 `captured` 로 둡니다. 코드를 읽고 옮겼으면 `derived` 입니다. 대부분 `derived` 입니다.
- `prefetch_related`, `annotate`, `aggregate`, `exists`, `select_for_update` 가 만드는 쿼리 수와 모양을 빠뜨리지 않습니다.

## 문구
AI 가 쓴 티가 나는 글은 읽히지 않습니다. 아래를 지킵니다.

- 한 문장에 사실 하나를 씁니다. 코드가 실제로 하는 일을 그대로 적습니다. 예: "리뷰 1건마다 잔액을 다시 더합니다."
- 비유를 쓰지 않습니다. "DB를 붙잡던", "병목의 주범" 대신 "배치가 도는 동안 DB CPU 90% 이상"처럼 일어난 일을 씁니다.
- `text` 는 합니다체 3문장 이하입니다. `bullets`·표 칸·`caption` 은 명사로 끝냅니다. 예: "회원마다 1번 조회".
- 제목은 명사입니다. 문장이나 "A에서 B로" 꼴을 쓰지 않습니다. 예: "지급 흐름", "쿼리 비교", "달라지는 응답".
- 다음은 쓰지 않습니다.
  - 예고와 마무리: "정리했습니다", "살펴보겠습니다", "결론적으로", "들어가며", "마치며"
  - 강조 수사: "핵심은", "중요한 것은", "본질적으로", "단순한 X가 아니라 Y"
  - 꾸미는 말: "다양한", "효율적으로", "대폭", "크게 개선", "원활", "획기적"
  - 결산 문장: "~인 셈입니다", "~하는 이유입니다", "~을 보여줍니다", "~와 직결됩니다"
  - 그림 설명: "왼쪽이 이전 방식이고", "아래 표는". 필요한 말은 `caption` 에 짧게 씁니다
  - 짧은 단정문 연타: "적립금은 돈입니다. 틀리면 안 됩니다."
  - 줄표(—), 굵은 글씨, 이모지
  - 문장 안에서 구색을 맞추려고 셋으로 묶은 나열. 실제 항목이 셋이면 그대로 씁니다
- 같은 대상은 처음 쓴 이름으로 끝까지 부릅니다.
- 식별자는 백틱으로 감쌉니다. 코드값에는 한국어 뜻을 붙입니다.
