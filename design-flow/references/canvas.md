# 디자인 캔버스 관례

캔버스는 claude.ai의 Design 타입 아티팩트다. 파일 형식(`.dc.html`, `<x-dc>`, `<sc-for>`, `renderVals()`)과 발행 방법(`root`, `file_path`, `files`)은 캔버스가 주는 SKILL.md와 `artifact-type/reference/format.md`가 정한다.

- 캔버스를 처음 다룰 때는 그 두 파일을 `Artifact` read로 읽는다.
- 이 파일은 그 위에 얹는 우리 관례만 적는다.

## 캔버스 찾기와 만들기

- **프로젝트 하나에 캔버스 하나를 쓴다.**
  - 메모리나 `design/` 폴더에 캔버스 링크가 있으면 그 캔버스에 줄을 추가한다.
  - 링크가 없으면 `Artifact` list로 찾는다.
- 캔버스가 없을 때만 `Artifact` quickstart(intent `design`)로 Design 타입에서 새로 만든다.
  - 제목은 "<프로젝트 이름> 디자인"으로 한다.
- 발행 전에 `project/canvas.json`을 다시 읽는다. 사용자가 캔버스에서 직접 고쳤을 수 있다.
- 사용자가 고친 보드를 덮어쓰지 않는다.

## 배치

**기능 하나가 한 줄이다.** 시안 A~D를 왼쪽부터 놓는다.

- 보드 사이 가로 간격은 80px이다.
- 줄 사이 간격은 넉넉히 둔다. 제목 노트(title1)가 줄 위 320px에 들어가야 하기 때문이다.

**줄 위 제목 노트**

- `{"kind":"title1","text":"<기능> — 시안 4종","maxW":<줄 너비>}`

**줄 오른쪽 끝의 "보는 법" 스티커**

- 주황 스티커이고, 너비 360px, 크기 `m`이다.
- 아래처럼 적는다.

  ```
  각 시안 보는 법
  · 위 줄 = 라이트, 아래 줄 = 다크
  · 왼쪽부터 = <상태 1>, <상태 2>, <상태 3>
  ```

**보드 제목**

- "<시안 글자> · <아이디어 이름>"으로 짓는다. 예: "A · 큰 문장", "B+D · 큰 숫자 + 그래프".
- 파일 이름은 `<기능><시안>.dc.html`이다. 예: `HomeA.dc.html`, `HomeBD.dc.html`, `HomeA2a.dc.html`.
- 단, 새 캔버스의 첫 보드(첫 기능의 시안 A)는 캔버스 형식상 `Main.dc.html`이어야 한다. 나머지 B~D는 `HomeB.dc.html`처럼 규칙대로 짓는다.

**확정 뒤 나머지 화면** 보드는 확정 시안 줄 바로 아래에 둔다. 예: `SignupA2.dc.html` "가입 A · 나머지 화면", `Detail.dc.html` "세부 화면 8종".

## 보드 크기

매체마다 다르다. `media.md`를 본다.

## 보드 안 구조

한 보드에 같은 장면을 여러 상태로 넣을 때는 `renderVals()`에 테마 객체(예: LIGHT, DARK)를 두고, `screens` 배열을 `<sc-for>`로 돈다. 이렇게 하면 장면 하나를 고칠 때 모든 상태가 함께 바뀌어서 서로 어긋나지 않는다. 아래는 앱 화면의 예다.

```js
// 색 값은 프로젝트의 디자인 기록에서 가져온다. 기록이 없으면 이번 작업에서 정한다.
const LIGHT = { bg: '<배경>', ink: '<글자>', sub: '<보조 글자>', hair: '<구분선>', ... };
const DARK  = { bg: '<배경>', ink: '<글자>', sub: '<보조 글자>', hair: '<구분선>', ... };
const mk = (dark, active) => { const t = Object.assign({}, dark ? DARK : LIGHT, active ? ACTIVE : BASE); return { t, ... }; };
return { screens: [mk(false,false), mk(false,true), mk(true,false), mk(true,true)] };
```

- 마크업에서는 `{{s.t.bg}}`처럼 쓴다.
- 상태 분기는 `<sc-if value="{{s.active}}">`로 한다.
- 버튼은 진짜 `<button>`으로 쓴다. 아이콘만 있는 버튼에는 `aria-label`을 붙인다.

## 생성 스크립트

보드가 여러 개이고 부품(헤더, 하단 탭, 공통 표시)을 함께 쓸 때는 보드를 손으로 하나씩 쓰지 않는다.

- 스크래치패드에 `gen_<기능>.py` 같은 생성기를 만들고, 공통 부품을 함수로 둔다.
- 하단 탭이나 글꼴처럼 전체에 걸친 변경은 `apply_<변경>.py`로 확정 보드 전부에 다시 적용한다.
- 생성기 이름과 다시 돌릴 순서는 메모리에 남긴다. 스크래치패드는 세션이 끝나면 사라질 수 있어서다.
- 오래 쓸 생성기는 프로젝트 `design/tools/`에 두는 것을 제안한다.

## 글꼴 올리기

- 글꼴 파일은 캔버스 자산으로 올린다(`asset: true`). 돌려받은 `/_blob/<id>`를 `<helmet>`의 `@font-face`에 넣는다.
- 공식 배포처에서 받는 글꼴은 파일 이름, 출처, 크기를 말하고 먼저 허락을 받는다.
- 라이선스(상업 이용, 앱 포함, 출처 표시)를 확인해 메모리에 남긴다.

## 확정 사본

- 확정 보드는 프로젝트 `design/<기능>/`에 복사한다. 예: `design/home/HomeA3.dc.html`.
- `design/home/canvas.json`에도 최신 배치를 복사해 둔다.
- 사본은 코드로 옮길 때 원본으로 쓴다.
- 확정한 색, 글꼴, 부품, 화면 목록은 프로젝트 `design/DESIGN.md`에 정리한다. 다음 작업은 그 파일부터 읽는다.
